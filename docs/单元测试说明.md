# 单元测试说明

> 被测模块：`js/core.js`（校园失物招领的核心业务逻辑，纯函数，无 DOM 依赖）
> 测试框架：**Mocha + Chai**
> 用例数量：**31 个**，全部通过

---

## 一、为什么选择 Mocha + Chai

- **Mocha** 是目前最流行的 JavaScript 测试框架，语法直观（`describe` / `it`），
  支持在浏览器和 Node.js 两种环境下运行，正好契合我们「既能在网页里点开看结果、
  又能在命令行 `npm test`」的需求。
- **Chai** 提供 `assert` 断言风格，配合 Mocha 使用非常自然，能清晰表达
  「相等 / 包含 / 抛出异常 / 属性存在」等断言。
- 二者都是纯 JavaScript 实现，零编译、零构建，学习成本低，适合课程项目。

## 二、我们是如何学习单元测试的

1. **先读官方文档**：Mocha 官网的 *Getting Started* 与 Chai 的 `assert` API 文档。
2. **看教程打基础**：参考廖雪峰的 JavaScript 教程与《测试框架 Mocha 实例教程》，
   理解 `describe`（一组测试）与 `it`（单个用例）的组织方式。
3. **动手写第一个用例**：先给最简单的 `resolvedText()` 写断言，跑通后再逐步扩展到复杂逻辑。
4. **理解断言风格**：从 `assert.equal` 开始，逐步使用 `assert.deepEqual`（比较对象）、
   `assert.property` / `assert.notProperty`（判断字段是否报错）、`assert.include`（包含子串）。
5. **理解白盒测试**：结合代码分支（每个 `if` 的两条路径）设计用例，做到「每条分支至少被执行一次」。

### 一份简易教程（三步跑起来）

```bash
# 1. 安装依赖
npm install mocha chai --save-dev

# 2. 写一个测试文件 hello.test.js
#    const assert = require('chai').assert;
#    describe('加法', () => {
#      it('1 + 1 应等于 2', () => assert.equal(1 + 1, 2));
#    });

# 3. 运行
npx mocha hello.test.js
```

若想在浏览器里看结果：新建一个 html，依次引入 `mocha.js`、`chai.js`，
调用 `mocha.setup('bdd')`，引入被测脚本与测试脚本，最后 `mocha.run()`。

**关键片段示例**（白盒边界值 + 不可变性）：

```js
it('用例3：物品名称长度边界（1 字过短、31 字过长、2 字与 30 字合法）', function () {
  assert.property(Core.validateItem(makeValid({ name: '伞' })), 'name');            // 下界-1
  assert.property(Core.validateItem(makeValid({ name: 'a'.repeat(31) })), 'name');  // 上界+1
  assert.notProperty(Core.validateItem(makeValid({ name: '雨伞' })), 'name');        // 下界
  assert.notProperty(Core.validateItem(makeValid({ name: 'a'.repeat(30) })), 'name');// 上界
});

it('用例21：更新状态不修改原数组', function () {
  var r = Core.updateStatus(items, '1', 'resolved');
  assert.equal(r[0].status, 'resolved');
  assert.equal(items[0].status, 'active');   // 原数组保持不可变
});
```

## 四、构造测试数据的思路

1. **工厂函数**：`makeValid()` 生成一份「合法表单数据」，`makeItem()` 生成一条标准记录，
   再用 `Object.assign` 覆盖单个字段。这样每个用例只关心「要测的那一个变量」，
   避免数据冗余、提高可读性。
2. **固定时间戳**：`timeAgo`、`sortItems` 等与时间相关的函数，测试时传入固定基准值
   （如 `now = 1000 * 60 * 60 * 24 * 10`），保证结果可复现，不受运行时刻影响。
3. **边界值优先**：长度、数量这类有上下界的字段，一律取「下界、下界-1、上界、上界+1」四点。
4. **等价类划分**：手机号、QQ 号按「合法格式 / 非法格式 / 位数不足」划分等价类，每类取样。

## 五、如何考虑测试人员的「刁难」

- **空值 / 缺字段**：用例2 直接传入 `{}`，验证是否逐项报错而不是抛异常崩溃。
- **类型异常**：`updateStatus` 传入非法状态 `'unknown-status'`，验证被安全忽略。
- **大小写与空格**：搜索用 `'airpods'` 匹配 `'AirPods Pro'`；关键词带首尾空格仍应命中。
- **安全攻击**：`escapeHtml` / `highlight` 用 `<script>`、`<img onerror>` 等恶意串，
  验证输出被转义、不会注入。
- **不可变性**：更新 / 删除函数都断言「原数组不被修改」，防止调用方数据被意外污染。

## 六、测试评估

31 个用例覆盖了核心模块的**所有分支**（校验的每个字段、搜索的命中与未命中、
筛选的单 / 多条件、排序的正 / 倒序、状态更新的合法 / 非法），并对边界值、异常输入、
安全性做了针对性设计。可以认为：**只要这些用例全部通过，核心业务逻辑在各种情况下
都能被正确处理**。后续若新增功能（如按地点筛选、多标签），只需在对应分组补充用例即可。
